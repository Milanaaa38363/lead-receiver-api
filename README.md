# Lead Receiver Service & CRM Dashboard

Единый сервис приёма заявок из разных каналов с автоматической дедупликацией клиентов по номеру телефона и интерактивным интерфейсом.

## 🔗 Ссылки
* **Живой проект (Render):** https://lead-receiver-api.onrender.com
* **Интерактивная документация (Swagger UI):** https://lead-receiver-api.onrender.com/docs

---

## 🛠 Стек и архитектура

* **Python / FastAPI** — за счёт Pydantic обеспечивается автоматическая и понятная валидация входных данных, а также генерация Swagger UI (`/docs`).
* **SQLAlchemy + SQLite** — хранение данных в базе данных с гарантией транзакционности.
* **HTML5 / CSS3 / JavaScript (Fetch API)** — клиентская часть в стиле Dark Mode с динамическим обновлением таблицы и подсветкой обновлённых сделок.

### Модель данных:
1. `Client`: хранит уникальный нормализованный номер (`+7XXXXXXXXXX`) и имя.
2. `Deal`: хранит текущую сделку клиента со статусом (`NEW`).
3. `LeadHistory`: хранит каждую попытку обращения (канал `source`, исходный сырой телефон, время).

---

## 💡 Принятые решения и почему

1. **E.164 Нормализация номеров:** Все входящие номера телефонов очищаются от скобок, тире и пробелов и приводятся к формату `+77XXXXXXXXX`. Это гарантирует надежный поиск дубликатов в базе данных.
2. **Изоляция истории заявок:** Повторные заявки от одного и того же клиента не создают дубликатов в таблице `Client`, а записываются в `LeadHistory`, сохраняя связь с имеющейся сделкой.
3. **Асинхронный UI без перезагрузки:** Использование Fetch API на фронтенде позволяет мгновенно получать ответы от API, сортировать сделки и выделять созданный лид цветом без полной перезагрузки страницы.
